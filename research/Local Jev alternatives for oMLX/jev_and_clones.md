# TypeSafe Jev / System One API and its open clones, reimplementations and competitors

Research date: 2026-09-29. Everything below is from 2026-09-14 through 2026-09-29 unless noted.

A note on sources: Jev spawned a large number of unofficial SEO, reseller and "directory" sites within days: jevtypesafeai.com, jevapi.org, jevapi.dev, jev.aitools.fyi, jevainews.com, jevdirectory.org, laya-ai.com, stackness.dev and others. None of them is TypeSafe. Where possible, the facts below cite typesafe.ai / docs.typesafe.ai or the GitHub repo itself. Facts that only come from aggregators say so. GitHub star counts and creation dates were read through the GitHub API on 2026-09-29.

## 1. What has TypeSafe published about Jev / System One, and is any part open weights?

### Takeaway
Jev is a closed, hosted "System One" decision model from TypeSafe AI. It was announced on 2026-09-14/15 in early access behind a waitlist. It has one endpoint, `POST https://api.typesafe.ai/v1/systemone`, and three typed question kinds: `choice`, `score` and `noul`. Pricing is $0.042 per million input tokens, output free. TypeSafe claims 70–500 ms latency. No weights, architecture, paper or training recipe are public. Only the SDKs and tooling are open.

### Cited Findings
**Launch and company**
- Launch blog post "Introducing System One Models and Jev" by Diogo Almeida (founder) is dated Sep 14, 2026. It says Jev is "available today in early access". Almeida says he helped build the instruction-following research behind ChatGPT at OpenAI, and the company spent two years in stealth — [TypeSafe blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The HN launch thread was posted 2026-09-15 and got 1,989 points and 520 comments (item 49717558), the largest Jev thread by far — [HN Algolia](https://news.ycombinator.com/item?id=49717558). Most third-party sites give 2026-09-15 as the release date — [MarkTechPost](https://www.marktechpost.com/2026/09/19/typesafe-ai-releases-jev/), [jevapi.dev (unofficial)](https://jevapi.dev/)
- Co-founders Erik Gafni and Sasha Sheng, $40M seed led by DCVC. This comes only from an unofficial site, not verified on typesafe.ai — [jevtypesafeai.com (unofficial)](https://www.jevtypesafeai.com/jev/system-one)
- Latent Space podcast/interview with Almeida: "Jev: System One Models for Prod, Not God" (2026-09-21) — [Latent Space](https://www.latent.space/p/jev)

**What it claims to be**
- TypeSafe says it built "a new model architecture, parallel sampler for maximum efficiency, and training method we call Reinforcement Learning for Calibrated Decisions (RLCD)". It describes Jev as "a frontier-intelligence function call: unstructured state in, typed probabilistic decisions out". It "gives up string generation" and "can't hallucinate" (meaning it cannot produce type errors) — [TypeSafe blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Speed claims: "End-to-end response time is 70ms-500ms", "40x-200x faster" than frontier LLMs, which take 3–329 s. The homepage claims "193.6x Faster, 444.6x Cheaper" on its workflow evals. The blog says these figures are "on the higher end of real world gains" — [TypeSafe blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [typesafe.ai](https://typesafe.ai)
- Pricing: "$0.042 / MTok ($42 per billion tokens)" for input; "Output tokens: FREE (too cheap to meter)". The homepage says "238x lower input price than Claude Fable 5.1". TypeSafe admits "We can't prove it isn't subsidized" — [TypeSafe blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [typesafe.ai](https://typesafe.ai)
- The name comes from Kahneman's System 1 (fast, intuitive thinking) in *Thinking, Fast and Slow*. The docs say System One models "do not write replies, produce code, or generate explanations of their reasoning" and that Jev accepts text only (strings, JSON objects, arrays). Images, audio and video are not supported "(yet)" — [docs.typesafe.ai](https://docs.typesafe.ai/concepts/system-one)
- Evaluation method: TypeSafe's "workflow evals" use the average of GPT-6 Astra and Claude Fable 5.1 as reference probabilities, not ground truth. This means the accuracy numbers measure agreement with those two models — [TypeSafe blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev); critique in [Victor Dibia](https://victordibia.com/explainers/jev/)

**API shape**
- A request has three required fields: `model` (e.g. `jev-latest`), `state` (a string, JSON object or array) and `questions` (a map keyed by ids you choose). Each question has a `type`, `instructions` and optional `criteria` — [apimodels.app reseller docs](https://apimodels.app/docs/jev), [docs.rs typesafe-jev](https://docs.rs/typesafe-jev/latest/typesafe_jev/)
- `choice`: up to 255 described options. It returns `choice`, `probabilities` per option and `confidence`. `score`: 2–10 ordered levels. It returns a fractional `score` (the probability-weighted mean of the level index), `probabilities`, `legend` and `confidence`. `noul` ("short for bernoulli"): returns `noul`, the probability (0–1) that the statement is true — [apimodels.app](https://apimodels.app/docs/jev), [Victor Dibia](https://victordibia.com/explainers/jev/)
- Example response: `{"model":"typesafe/jev-1.13-20260917","answers":{"department":{"type":"choice","choice":"billing","probabilities":{...},"confidence":0.83},"is_urgent":{"type":"noul","noul":0.96}},"usage":{"input_tokens":427,"output_tokens":73,"cost":...}}`. The version string seen in the wild is jev-1.13.0 — [jevapi.org (unofficial)](https://jevapi.org/docs/), [apimodels.app](https://apimodels.app/docs/jev)
- All questions in one request are evaluated in parallel against the same state, "so a request with hundreds of questions takes about as long as one with a single question". Questions cannot see each other — [docs.rs typesafe-jev](https://docs.rs/typesafe-jev/latest/typesafe_jev/)
- There is no temperature, seed or length parameter — [Victor Dibia](https://victordibia.com/explainers/jev/)
- Context window: sources disagree. "approximately 32,000 input tokens shared by state and questions" — [Experiential](https://platform.experientiallabs.ai/models/jev-latest), [jevapi.org](https://jevapi.org/docs/). Other sources say "64k tokens per request" — [apimodels.app](https://apimodels.app/docs/jev), [jevapi.dev](https://jevapi.dev/)
- Distribution: official Python (`typesafe-sdk`, which reads `TYPESAFE_BASE_URL` and `TYPESAFE_API_KEY`) and JS SDKs. Also available on OpenRouter, LiteLLM pass-through (`/typesafe/v1/systemone`) and the Vercel AI Gateway (`typesafe-ai/jev`) — [OpenRouter](https://openrouter.ai/typesafe), [LiteLLM](https://docs.litellm.ai/docs/pass_through/typesafe), [jev-doom README](https://github.com/olivier-motium/jev-doom)

**Architecture and openness**
- On HN, the CEO called the architecture "close to the chest for now". His one statement about the mechanism was: "strings (and all sequential data structures) are not allowed at all - this is how we make sure all outputs can be computed in parallel" — quoted in [Victor Dibia](https://victordibia.com/explainers/jev/)
- RLCD is not published. TypeSafe publishes no reliability diagram or ECE. Its one accuracy-by-confidence figure is 27 of 30 correct above 0.9 confidence, on an older model — [Victor Dibia](https://victordibia.com/explainers/jev/)
- Weights: "No — Jev is a hosted model … The model itself runs on TypeSafe's servers". The open parts are tooling only (awesome-jev, jev-mcp, the LangChain integration) — [jevtypesafeai.com (unofficial)](https://www.jevtypesafeai.com/); confirmed by [stackness.dev](https://stackness.dev/blog/how-do-you-run-system-one-decision-models-locally-ollaya-laya-mlx-and-the-runtime-slot) ("TypeSafe has not released Jev's weights") and [scriptbyai](https://www.scriptbyai.com/jev-open-source-alternatives/)
- Independent measurements: hosted median latency is about 236–276 ms, including the network, per third-party benchmarks (AbdelStark/jev-benchmarks, nibzard/decision-model-benchmark) as cited by [Ollaya](https://ollaya.dev/). About 380 ms round trip per [stuntd author](https://bittide.aicompass.dev/article/012b16f3-88e1-482f-a40d-2c51ffbd0ad8). One third party measured ECE 0.0588 and 96.5% accuracy on 662 prompt-injection messages — [Victor Dibia](https://victordibia.com/explainers/jev/). Ollaya claims Jev's ECE is 0.246, which conflicts with that figure. The protocol is unknown — [Ollaya](https://ollaya.dev/). DecisionEval could not reproduce the model card's 0.144 ECE — [DecisionEval](https://decisioneval.dev/models/typesafe-jev/)
- A Sep 23 HN comment asks "Is benchmarking Jev still a ToS violation?", which suggests the terms restricted benchmarking at some point — [HN 49812769](https://news.ycombinator.com/item?id=49812769)

**The jev-doom reference repo**
- `olivier-motium/jev-doom` (created 2026-09-21, MIT, 2 stars) is an independent experiment. Jev plays Freedoom through ViZDoom from structured engine observations (entity positions, floor cells), not pixels. Code builds the legal choices and runs the chosen action. It calls `api.typesafe.ai/v1/systemone` with `jev-latest`, or the Vercel Gateway. It has a $15 spending cap by default — [GitHub](https://github.com/olivier-motium/jev-doom)
- TypeSafe's own launch demo was also Doom. HN commenters discussed "a machine playing Doom with low-latency as the first demo" — [HN 49717558](https://news.ycombinator.com/item?id=49717558)

### Inferences
- The API is simple and fully documented, so it has become a de facto wire protocol. The model is the only closed part. This explains why dozens of "base URL swap" servers appeared within 1–10 days.
- Several people independently guess that Jev is a scoring/readout model. It reads probabilities for a fixed option set at one position rather than generating tokens. The 255-option cap supports that guess. It is unconfirmed.

### Gaps
- No TypeSafe model card, paper or parameter count was found. The "model card ECE 0.144" that DecisionEval cites was not located at a primary URL.
- The authoritative context size (32k vs 64k) is unresolved. docs.typesafe.ai/models was not fetched.
- The founder and funding details come only from an unofficial site.

## 2. Open-source / open-weights projects that clone, imitate or compete with Jev

### Takeaway
There is a very large ecosystem. `gh search repos jev` returns hundreds of repos created 2026-09-16 or later. The projects fall into four groups: (a) dedicated open-weight decision models (Laya, Kev, Jeff, Von, Decider, Tev1, JevK5, CLM, Verdict, CUA-S1); (b) "logit readout" servers that turn an existing open LLM into a `/v1/systemone` endpoint (SemIf, verdict, AnyJev, simple-jev, openjev-sglang, llamacpp-jev, jevper, sys1); (c) runtimes and gateways (Ollaya, laya-serve, Arbiter, Decis, stuntd, Codiv); and (d) prompted JSON stand-ins (githubnext/localjev). Most expose the same `POST /v1/systemone` wire format, so the TypeSafe SDK works against them after a `TYPESAFE_BASE_URL` change. For Apple Silicon, the best-supported options are Laya through laya-mlx or laya-coreml (about 5–14 ms), Jeff (MLX, about 28 ms on an M4 Max), Kev (MLX, 0.8B–9B), SemIf (MLX backend), OpenJev (DiffusionGemma on MLX) and LocalJev (oMLX).

### Cited Findings

#### A. Dedicated open-weight decision models
- **Laya** (NandhaKishorM/laya, Convai Innovations; created 2026-09-18, about 28.7k stars, Apache-2.0). A "non-autoregressive System 1 decision engine" on ModernBERT and mmBERT encoders (421M English, 322M multilingual, plus a typed-decisions checkpoint). It answers choice/score/noul in a single forward pass in about 33 ms. It claims RLCD-style training "against strictly proper scoring rules" and uses a Router to pick the checkpoint. `pip install laya`, HF `convaiinnovations/laya`, extras for serve/MCP/ONNX. The multilingual checkpoint reads up to 8,192 tokens — [GitHub](https://github.com/NandhaKishorM/laya). The author says he built non-autoregressive decision models a year before Jev. HN commenters cite Laya as prior art — [HN 49717558 comments](https://news.ycombinator.com/item?id=49777194), [HN "Open-sourced jev architecture last year", 97 pts](https://news.ycombinator.com/item?id=49736660)
  - Weakness on large label sets: Banking77 (77 intents) scores 0.425 for Laya vs 0.870 for Jev — [laya-ai.com](https://laya-ai.com/jev-alternatives). About 38% vs 76% per dhruvmehra/jevbench, as cited by [stuntd](https://bittide.aicompass.dev/article/012b16f3-88e1-482f-a40d-2c51ffbd0ad8). The Laya card reports 76.6% top-choice accuracy vs a published Jev 72.7% on its own 2,000-decision split — [dev.to](https://dev.to/jmeg8r/how-to-run-laya-typed-decisions-locally-instead-of-calling-jev-4pj9)
  - **Apple Silicon ports**:
    - `mizorewww/laya-mlx` (2026-09-19, about 6.6k stars): native MLX, `pip install laya-mlx`. On an M3 Max in FP16: P50 13.4 ms (421M) / 7.4 ms (322M multilingual) for one short question, 50-question throughput 147–395 q/s, peak memory about 0.7–0.9 GiB. 378/378 validation comparisons matched upstream — [GitHub](https://github.com/mizorewww/laya-mlx)
    - `mizorewww/laya-coreml` (about 1.5k stars): Core ML / Neural Engine, about 5 ms short decisions on an M3 Max — [GitHub](https://github.com/mizorewww/laya-coreml)
    - `afshinm/laya-mps`: PyTorch MPS, about 32 ms median, about 2.1 GiB RAM on an M5 Pro — [vuink mirror](https://vuink.com/post/tvguho-d-dpbz/afshinm/laya-mps)
    - `virajbhartiya/laya-vs-jev`: local MLX vs hosted Jev side by side (T-Rex game) — GitHub search
- **Kev** (jaredpalmer/kev; 2026-09-17, about 7.9k stars, Apache-2.0; HN 462 pts on 2026-09-21). Qwen3.5/3.8-based decision models at 0.8B/4B/9B/27B, built on an architecture from the blog post "Jev's Architecture Unmasked" (archerhume.com). `python -m kev.serve` exposes `/v1/systemone`, and the TypeSafe SDK works unchanged. Each checkpoint ships a fitted temperature. It runs on MLX on Apple Silicon: 0.8B on "any Apple Silicon Mac", 4B/9B on a "32 GB Mac". On new-source accuracy: Kev-27B 0.848, Jev 0.857, Kev-4B 0.817, Kev-0.8B 0.648. On an Apple M5, Kev-4B takes 721 ms for five questions, or 136 ms when the text is cached. On an H100 it takes 18.1 ms — [GitHub](https://github.com/jaredpalmer/kev), [HN](https://news.ycombinator.com/item?id=49783999)
- **Jeff** (firelex/jeff; 2026-09-28, about 1.1k stars; HN 565 pts on 2026-09-28). Fine-tunes of Qwen3.5-0.8B/2B and Gemma 4 E2B for zero-shot choice/noul/score, same request format as Jev. v1.1 (2026-09-29) supports up to 254 options. About 22 ms on an RTX PRO 6000 and **28 ms on an Apple M4 Max (MLX)**, with `JEFF_BACKEND=mlx`. Overall accuracy on 5 benchmarks: 79.1 (0.8B), 82.0 (2B), vs Jev's published 83.0. It was trained entirely on local hardware from the AutoJev recipe. HF: `mstrasser/Jeff-Qwen3.5-0.8B` and others — [GitHub](https://github.com/firelex/jeff), [HN](https://news.ycombinator.com/item?id=49883844)
  - Name collision: a different "jeff" by Logan Markewich (LlamaIndex) wraps Knowledgator's GLiFormer (575.6M) behind `/v1/systemone` — [jevainews (aggregator)](https://jevainews.com/news/jeff-local-gliformer/). There is also Gestalt-Lab/jeff — GitHub search
- **Von** (wfzyx/von; 2026-09-18, 776 stars, Apache-2.0). A 395M ModernBERT encoder, non-autoregressive, CPU-served, English only. `von serve` is "byte-compatible" with `/v1/systemone`. It auto-selects cuda/**mps**/openvino/cpu. `pip install von-sdk` — [GitHub](https://github.com/wfzyx/von)
- **Decider** (Mapika/decider; 2026-09-16, 972 stars, Apache-2.0). Qwen3.5 fine-tunes (2B/4B/35B MoE) that read option-letter logits in one pass. Choice supports 2–255 options — [GitHub](https://github.com/Mapika/decider), [laya-ai.com](https://laya-ai.com/system-one-models)
- **Tev1** (togethercomputer/tev1; 2026-09-23, MIT). "Open-weight, Jev-inspired decision model finetuned on top of Qwen3.5 4B" (LoRA letter-picker) — [GitHub](https://github.com/togethercomputer/tev1)
- **JevK5** (allebee/jevk5; 2026-09-22, Apache-2.0). Qwen3.5-4B with a distilled LoRA, read by answer letters, 16k context — [GitHub](https://github.com/allebee/jevk5), [razorback16/openjev README](https://github.com/razorback16/openjev)
- **CLM** (Contrastive-LM/CLM; 2026-09-23, about 2.5k stars). Contrastive heads over Qwen3-8B — [openjev README](https://github.com/razorback16/openjev)
- **AutoJev** (denis-pplx/autojev; 2026-09-19). Full-weight Qwen decision model plus training code and REST API. AutoJev-27B's published overall score is 84.9, above Jev's 83.0 in Jeff's table — [GitHub](https://github.com/denis-pplx/autojev), [Jeff README](https://github.com/firelex/jeff)
- **Verdict / openJev-verdict-2.0** (Heman10x-NGU; 151M ModernBERT encoder, runs in the browser) — [GitHub](https://github.com/Heman10x-NGU/Verdict-open-jev)
- Smaller or reproductions: `kshetrajna12/reflex` (Qwen3.5 re-creation), `TianyuCodings/NanoJev` (about 2.4k stars, "nano replica"), `vinnylarouge/jevlike` (HN 169 pts: "Reverse-engineered Jev-like model"), `kyegomez/open-jev` (PyTorch first-principles), `org2AI/wald-4b`, `reoring/fern` (4B distilled from DeepSeek), `iapp-technology/openthai-systemone` (0.8B Thai), `malevrigns/agent-jev` (AgentJev-0.6B), `feder-cr/jev` "jevos" (yes/no only; returns 422 for choice/score; 0.815 vs Jev 0.927 on 2,000 items) — GitHub API; [jevdirectory (aggregator)](https://www.jevdirectory.org/articles/serving-system-one-locally)
- **Rizzo Flow** (Rizzo-AI-Academy/rizzo-flow; 2026-09-21, 758 stars, Apache-2.0). Spark-X2.5 plus a LoRA on llama.cpp (Metal supported), port 8017. 0.648 accuracy at Q8_0 vs 0.574 for the base model and 0.727 for Jev's dataset-card figure. It says the probabilities are uncalibrated — [jevdirectory](https://www.jevdirectory.org/articles/serving-system-one-locally)
- **Bespoke Nimble** (bespokelabsai/nimble, about 1.9k stars). 9B generative LoRA — [jevainews](https://jevainews.com/news/github-next-localjev/)
- **CUA-S1-FORMS** (trycua; Show HN on 2026-09-19, 95 pts). An open 706,048-parameter (2.8 MB) "System One" model for form-filling computer use. It reports 99.95% top-1 accuracy on synthetic data — [HN](https://news.ycombinator.com/item?id=49767564), [runtimewire](https://runtimewire.com/article/cua-open-sources-cua-s1-forms-model)

#### B. Readout servers over any open LLM (no training)
- **SemIf, formerly OpenJev** (TheoLeeCJ/SemIf-OpenJev; 2026-09-16, about 4.6k stars, MIT). Reads declared option logits from a frozen model (Qwen3.5-4B, MiniCPM5, Qwen3.8-27B EXL3). Has a **native MLX backend** (`pip install -e '.[mlx]'`, `--backend mlx`) with "parallel shared-state decisions on macOS arm64", plus PyTorch/MPS (added 2026-09-22), a llama.cpp GGUF backend and a WebGPU browser demo. On an RTX 3090 it answered 21 binary criteria in 1.02 s vs 5.33 s for autoregressive JSON. Per-workload temperature calibration was added 2026-09-22 — [GitHub](https://github.com/TheoLeeCJ/SemIf-OpenJev)
- **OpenJev (razorback16)** (2026-09-18, 538 stars, Apache-2.0). Reads DiffusionGemma 26B-A4B as a diffusion canvas. Runs on vLLM (NVIDIA) **or MLX on Apple silicon**. Supports text and image questions. Wire-compatible and accepts the `jev-latest`/`jev-preview` aliases. Also serves Laya, Verdict, CLM and JevK5 as model ids. Confidence is `1 − H(p)/ln K`. It is hosted free on Codiv — [GitHub](https://github.com/razorback16/openjev)
- **verdict** (khimaros/verdict; 2026-09-20, GPL-3.0). A Python server in front of llama-server or llama-swap with any GGUF. Reads label-token mass at one position. Its conformance test is the unmodified `browser-use/jev-ultrafast` client. It warns that a small Gemma reported confidence 1.000 on wrong answers — [GitHub](https://github.com/khimaros/verdict), [jevdirectory](https://www.jevdirectory.org/articles/serving-system-one-locally)
- **daseinlabs/open-jev** (2026-09-17, 121 stars, MIT). Gemma 3 4B one-pass option scoring. The **MLX backend is the default on Apple silicon**, and scoring requests take "about 90 ms each". Has a `/v1/systemone` route and custom fine-tuning — [GitHub](https://github.com/daseinlabs/open-jev)
- **AnyJev** (nokia-applied-research; 2026-09-21, 965 stars, Apache-2.0). Reads hidden states of an existing LLM, with debiasing and calibration. HF and vLLM — [GitHub](https://github.com/nokia-applied-research/AnyJev)
- **simple-jev** (featherless-ai; 2026-09-18, 574 stars): "Turn any open model into a classifier/jev endpoint" — GitHub API
- **openjev-sglang** (ekzhang; 2026-09-17, 334 stars): prefill-only, Qwen3.6-35B-A3B on SGLang — [jevlist](https://jevlist.ai/projects/openjev-sglang)
- **open-alternative-jev** (ikermoel; Apache-2.0, import name `so1`): an in-process library for HF and vLLM. It has no HTTP server and says "Not a reproduction of Jev" — [GitHub](https://github.com/ikermoel/open-alternative-jev)
- **LLM2Jev** (Yinsongxu; 375 stars): local LLMs to Jev-style decisions, text and images, prefill only — GitHub API
- **llamacpp-jev** (NakliTechie; MIT): a wrapper over an unmodified llama.cpp binary. "Raw label softmax, not calibrated" — [HN comment](https://news.ycombinator.com/item?id=49848269)
- **jevper** (PyPI, Apache-2.0). Adds the Jev interface to any OpenAI-compatible model through logprobs, GBNF grammar (llama.cpp), structured-JSON or discrete modes — [PyPI](https://pypi.org/project/jevper/)
- **sys1** (alvarobartt; Rust, candle, CPU/CUDA/**Metal**), **jev-rs** (yijunyu; Rust), **llm2jev** (tic-top), **Jev-Compatible** (David-Lolly, SGLang/vLLM), **openjev.cpp** (cappuch, llama.cpp fork), **jev-skills/openjev-multimodal** (Mac, Qwen with llama.cpp and Metal), **CoderInPajamas/JEV-MLX** (MLX, 4 stars), **mikkel-bergmann/jev-local-decision-engine** (MPS), **hr98w/jev-visual** (Apple Silicon visual) — GitHub API search, 2026-09-29
- "Jev in 25 Lines of Python" (nobodywho.ai; HN 691 pts, 2026-09-23). Shows the core logit-readout trick. HN commenters note that prompt processing is identical to Jev, and each question needs only one or two tokens of readout in a single batch — [HN](https://news.ycombinator.com/item?id=49812769)
- Victor Dibia's experiments on open Qwen2.5 1.5B/7B: scoring was 7×–54× faster than generating probabilities. **Base models were near-calibrated (ECE 0.02–0.05), while instruct models were overconfident (ECE 0.10–0.18).** Temperature scaling on 600 labels brought the 7B instruct model from 0.10 to 0.03. A stock 7B instruct reached 93.0% vs Jev's 96.5% on the same prompt-injection set (the measurements come from different people) — [victordibia.com](https://victordibia.com/explainers/jev/)

#### C. Prompted JSON stand-ins (relevant to oMLX)
- **LocalJev** (githubnext/localjev; 2026-09-18, about 800 stars, MIT). A Bun/TypeScript `/v1/systemone` server in front of **oMLX** (default upstream `127.0.0.1:8000`, model `diffusiongemma-26B-A4B-it-4bit`). It prompts the model to write a JSON probability vector, retries malformed output and normalizes. The README says these probabilities are self-reported, not logit reads, and that "the normal oMLX API does not expose" the structured-read primitives that razorback16/openjev needs. It notes LM Studio could not load DiffusionGemma as of 2026-09-18 — [GitHub](https://github.com/githubnext/localjev)
  - Bake-off on an M5 Max 64 GiB with oMLX 0.6.4 (1,200 requests, 120 gold labels). Short-input macro accuracy: Qwen3.6-35B-A3B 76.7%, Gemma 4 26B-A4B 75.0%, DiffusionGemma 26B-A4B 74.2%, Gemma 4 E4B 63.3%, E2B 45.8%. p50 latency 0.52–1.21 s — [jevainews (aggregator)](https://jevainews.com/news/github-next-localjev/)
- Other OpenAI-compatible wrappers: `9pings/notjev`, `vladvlsu/jev_ollama_ornith` (Ollama plus FastAPI), `Apothic-AI/jeb` (Cloudflare Workers plus OpenRouter) — GitHub API

#### D. Runtimes, gateways and hosting for open decision models
- **Ollaya** (ollaya-dev/ollaya; repo created 2026-09-23, 993 stars, Apache-2.0; HN 613 pts on 2026-09-25). "Ollama for decision models". Serves `/v1/systemone` and `/v1/models` on `localhost:11435`. The TypeSafe Python SDK 0.7.1 works unchanged. Models: laya, decider, nli, gliclass, and later kev, von, winnow, jevk5 and qwen3guard. It has a macOS Apple-silicon desktop app, but **on Mac only laya and nli use the GPU via MLX; the rest run on CPU**. It is not affiliated with Ollama — [ollaya.dev](https://ollaya.dev/), [Glonce](https://glonce.com/ollaya-runs-typesafe-jev-decision-models-locally-ollama/), [HN](https://news.ycombinator.com/item?id=49848269). Release 0.7.3 was out by 2026-09-27 — [stackness](https://stackness.dev/blog/how-do-you-run-system-one-decision-models-locally-ollaya-laya-mlx-and-the-runtime-slot)
- **Arbiter** (0xBakeer): serves Laya or your own model on NVIDIA **or Apple Silicon**, Jev-compatible. **Decis** (chaitin): one Docker image per engine (Laya, Kev). **laya-server** (1Panel-dev), **laya-serve** (stiermid), **hearim** (Go gateway), **BrighTO_Router** (Rust), **HarnessRouter/SystemOneHarness** — GitHub API
- **stuntd** (bladedevoff; 2026-09-23, Apache-2.0). A local proxy that records your provider's decisions, trains a head on a frozen Laya encoder, and takes over when agreement reaches the target. Head p50 is 22 ms on CUDA — [post](https://bittide.aicompass.dev/article/012b16f3-88e1-482f-a40d-2c51ffbd0ad8)
- **Jevstiller** (HN 2026-09-29): distills Jev into a local model with a disagreement bound — [HN](https://news.ycombinator.com/item?id=49891769)
- **PostHog/jeeves** (2026-09-29, HN 233 pts): "Reasoning improves Jev-like decision models" — [GitHub](https://github.com/PostHog/jeeves)
- Gateways: vLLM, LocalAI and NVIDIA Dynamo support is at the pull-request stage (unconfirmed). GoModel forwards S1 endpoints — [stackness](https://stackness.dev/blog/how-do-you-run-system-one-decision-models-locally-ollaya-laya-mlx-and-the-runtime-slot), [HN comment](https://news.ycombinator.com/item?id=49848269)
- Benchmarks for comparing models: JevBench (fstandhartinger/jevbench, 2026-09-19; HN "Show HN: JevBench" 153 pts), dhruvmehra/jevbench, the `LocalLLaMA/typed-decisions` dataset, DecisionEval — [HN](https://news.ycombinator.com/item?id=49800574), [DecisionEval](https://decisioneval.dev/models/typesafe-jev/)

### Inferences
- For a local Mac setup that needs broad zero-shot accuracy with many options, the LLM-readout approaches (Kev, Jeff, SemIf, Decider, or a logprob shim over an oMLX or llama.cpp model) are closer to Jev than the small encoders. Laya and Von are much faster but weak on large label sets unless you fine-tune them.
- oMLX's standard OpenAI-compatible API is enough for prompted JSON (LocalJev) or for logprob-based readout if it returns `top_logprobs`. It is not enough for razorback16's diffusion structured read. This conclusion comes from the LocalJev README.
- Raw readout probabilities from instruct models are overconfident. Every serious project either ships a fitted temperature (Kev), adds calibration tooling (SemIf) or warns that probabilities are uncalibrated (verdict, llamacpp-jev, Rizzo, LocalJev).

### Gaps
- Hugging Face search was not run directly. The HF model ids above come from project READMEs.
- No independent head-to-head of the Mac options under one protocol was found. All latency and accuracy numbers are self-reported by each author.
- Whether oMLX exposes `logprobs`/`top_logprobs` well enough for a true logit-readout shim was not checked.

## 3. What users on HN, Reddit (r/LocalLLaMA) and X say about local alternatives

### Takeaway
From the launch day on, the loudest HN theme was that the concept is not new: zero-shot classification, BART-NLI, logprob classifiers and Laya came before it. The second theme was demand for local or open weights: "Having to call an API for something that's main benefit is speed is orthogonal to their ethos". Community consensus by late September: Jev still leads out of the box, especially on many-label tasks. Open models close the gap after fine-tuning on your own data. The suggested workflow is to prototype on Jev, collect labels, then fine-tune a small open model.

### Cited Findings
- On launch-thread HN, YPCrumble asked, "What are peoples' thoughts on whether a local version of Jev is possible? Having to call an API for something that's main benefit is speed is orthagonal to their ethos" (2026-09-16). spacedoutman: "The fact this isn't open-source is troublesome". rattray: "Open weight or even closed with a proprietary license, I'd definitely like to be able to run it locally" — [HN 49717558](https://news.ycombinator.com/item?id=49717558)
- Prior-art claims: "Jev isn't new. There has already been an open source project for a year, now called Laya" (niutech, 2026-09-20). "zero-shot classification using e.g. Facebook BART has been available for years" — [HN 49717558](https://news.ycombinator.com/item?id=49777194)
- Technical guesses: padolsey asked whether Jev is "a discriminative head on a transformer, no decoding" and said he got similar speed with a 4B Qwen but "could not reach the level of intelligence". NitpickLawyer described getting confidence from `logprob("YES") - logprob("NO")` with grammars. porridgeraisin described RLCD as essentially proper-scoring-rule RL ("calibrated RL") — [HN 49717558](https://news.ycombinator.com/item?id=49717558)
- On the Ollaya thread (2026-09-25/26), _menelaus wrote: "The moat is the RL synthetic data pipeline … not the model architecture and training scripts, which are trivial". mattstir wrote that the "open source decision models need to be fine-tuned". lgas reported that Laya was comparable to Jev on easy semantic-grep queries, but "the gap widened in favor of jev" on harder ones — [HN 49848269](https://news.ycombinator.com/item?id=49848269)
- On the Jeff thread (2026-09-28), nico said that embeddings plus a logistic classifier "matches or beats Jev and Laya in all basic classification tasks" (AG News and others). yfontana wrote: "Jev is a classifier. - Other notable HN posts: "OpenAI is well positioned to fast-follow Jev" (328 pts, 2026-09-22) — [arcturus-labs](https://arcturus-labs.com/blog/2026/09/21/will-openai-eat-jevs-lunch/). ## 4. Commercial competitors with similar "fast calibrated choice" APIs, and whether they have open versions

### Takeaway
The main commercial competitor is OpenAI's Decisions API. It was announced at DevDay 2026, about two weeks after Jev (around 2026-09-29), in limited preview. It is powered by GPT-6 Luna, takes text or images, reports about 150 ms latency, has no announced pricing and no open weights. Its confidence is reported to be self-reported by the model rather than trained for calibration. Other hosted options mostly serve open models: Codiv (free tier, OpenJev and other open System One models), and resellers or gateways for Jev itself (OpenRouter, Vercel AI Gateway, LiteLLM, TokenRa, APIMODELS, Experiential).

### Cited Findings
- OpenAI Devs: "Give your app real-time decision-making with Decisions API, powered by GPT-6 Luna. Define questions and possible answers to classify content, route requests, or choose an agent's next action. Available in limited preview." — [X @OpenAIDevs](https://x.com/OpenAIDevs/status/2105003318917697873); also in [OpenAI DevDay 2026 recap](https://openai.com/index/devday-2026-recap/)
- It returns predefined answers with confidence scores "in 150 milliseconds" and is built on the small Luna model — [The New Stack](https://thenewstack.io/openai-decision-api-luna/). The announcement came "exactly two weeks after TypeSafe AI launched Jev". Pricing is not announced. Reportedly it fills a JSON schema with self-reported probabilities that are not calibrated against outcomes — [pasqualepillitteri.it via search snippet](https://pasqualepillitteri.it/en/news/19372/openai-decisions-api-jev) (page fetch failed; the claim is secondary)
- Before the Decisions API, OpenAI's logprobs and tool-calling were already used as "micro-classifiers" — [arcturus-labs](https://arcturus-labs.com/blog/2026/09/21/will-openai-eat-jevs-lunch/)
- **Codiv**: an "inference platform for open System One models". It offers 100M free input tokens with no card at `https://api.codiv.ai/v1/systemone` and serves the OpenJev (DiffusionGemma), Laya, Verdict, CLM and JevK5 models. The underlying server is open source (razorback16/openjev) — [codiv.ai](https://codiv.ai/), [openjev README](https://github.com/razorback16/openjev)
- **Regolo** (EU): a hosted ModernBERT capability classifier (149M, open on HF as `regolo/modernbert-capability-classifier`) and an open brick-SR1 gateway. It is positioned against Jev for routing — [regolo.ai](https://regolo.ai/jev-and-system-one-models-benchmarks-open-source-alternatives-and-when-to-use-them/)
- **Cua (trycua)**: CUA-S1 System One models for computer use. The first one, CUA-S1-FORMS, is open source — [HN](https://news.ycombinator.com/item?id=49767564)
- Resellers of Jev itself: OpenRouter, TokenRa, APIMODELS ($0.05/MTok, a markup), Experiential, Vercel AI Gateway, LiteLLM pass-through — [OpenRouter](https://openrouter.ai/typesafe), [apimodels.app](https://apimodels.app/docs/jev), [jevapi.org](https://jevapi.org/docs/), [Experiential](https://platform.experientiallabs.ai/models/jev-latest)
- A "classifier.dev" hosted option is mentioned only in passing by an aggregator. It was not verified — [jev.aitools.fyi](https://jev.aitools.fyi/tools/jaredpalmer-kev)

### Inferences
- The OpenAI Decisions API makes the choice/confidence API shape a mainstream product category. Whether it is wire-compatible with `/v1/systemone` is unknown. Nothing suggests OpenAI will release open weights.

### Gaps
- No OpenAI docs page for the Decisions API was fetched. The request/response shape, pricing and calibration claims are unverified at the primary source.
- No other big-lab competitor (Google, Anthropic, Groq, Together as hosted) with a dedicated decision endpoint was found. Together's contribution is the open Tev1 model, not an API.
